موتور ریسک کمی

Quantitative risk engine

محاسبهٔ Value-at-Risk با سه روش مستقل — تاریخی، پارامتریک و مونت‌کارلو — به‌همراه Expected Shortfall، شش سناریوی استرس، تحلیل همبستگی، شاخص تمرکز HHI و سایزپوزیشن پویا.

Value-at-Risk via three independent methods — historical, parametric and Monte Carlo — plus Expected Shortfall, six stress scenarios, correlation analysis, the HHI concentration index, and dynamic position sizing.

📡

داده و پایش زنده

Live data and monitoring

یکپارچگی با صرافی نوبیتکس: چرخهٔ کامل سفارش، موجودی‌ها، پوزیشن‌ها و قیمت لحظه‌ای. جریان داده از طریق WebSocket با احراز هویت توکن و اشتراک موضوعی.

Nobitex exchange integration: full order lifecycle, balances, positions and live prices. Data streams over an authenticated WebSocket with topic subscriptions.

🔐

امنیت و دسترسی

Security and access control

هش bcrypt با cost 12، توکن JWT با انقضای ۳۰ دقیقه، سه نقش Admin/Trader/Viewer، و گاوصندوق جدا برای کلید صرافی با مجوز ۰۶۰۰ که هرگز در دیتابیس ذخیره نمی‌شود.

bcrypt hashing at cost 12, JWT tokens with a 30-minute lifetime, three roles (Admin/Trader/Viewer), and an isolated vault for exchange keys at mode 0600 that is never stored in the database.

معماری Architecture

چهار کانتینر، یک شبکه

Four containers, one network

مرورگر هرگز مستقیماً به بک‌اند وصل نمی‌شود. فراخوانی‌ها هم‌مبدأ (/api/v1/*) هستند و Next آن‌ها را به بک‌اند پراکسی می‌کند — بنابراین استقرار پشت reverse proxy یا میزبان پیش‌نمایش هیچ تغییری در سمت مرورگر نیاز ندارد.

The browser never calls the backend directly. Requests are same-origin (/api/v1/*) and Next proxies them to the backend — so deployment behind a reverse proxy or a preview host needs no browser-side configuration.

پرسش‌های پرتکرار FAQ

آنچه کاربران می‌پرسند

What people ask

پول واقعی خرج می‌شود؟ Does this spend real money?

خیر. در این نسخه بخش معاملات روی حالت آزمایشی (Paper Trading) کار می‌کند: سفارش شبیه‌سازی می‌شود و هیچ پول واقعی جابه‌جا نمی‌شود. یکپارچگی نوبیتکس برای گرفتن قیمت، موجودی و پوزیشن است.

No. In this version trading runs in paper-trading mode: orders are simulated and no real funds move. The Nobitex integration is used for prices, balances and positions.

داده‌هایم کجا ذخیره می‌شود؟ Where is my data stored?

روی سرور خودتان. PostgreSQL و گاوصندوق کلیدها هر دو محلی‌اند. هیچ داده‌ای به سرور بیرون ارسال نمی‌شود. کلید API صرافی بیرون از دیتابیس، در فایلی با مجوز ۰۶۰۰ نگه داشته می‌شود تا نشت دیتابیس کلید شما را لو ندهد.

On your own server. PostgreSQL and the key vault are both local. No data is sent to an external server. The exchange API key is kept outside the database, in a file at mode 0600, so a database leak does not expose it.

روی موبایل کار می‌کند؟ Does it work on mobile?

بله. برنامه یک PWA است: در مرورگر موبایل گزینهٔ «Add to Home Screen» را بزنید تا مثل یک اپلیکیشن بومی نصب شود.

Yes. The app is a PWA: in a mobile browser choose "Add to Home Screen" and it installs like a native application.

چند کاربر می‌تواند هم‌زمان استفاده کند؟ Can several people use it at once?

بله. سه نقش وجود دارد: Admin (کنترل کامل)، Trader (معامله) و Viewer (فقط مشاهده). Admin از طریق POST /api/v1/auth/register کاربر می‌سازد.

Yes. There are three roles: Admin (full control), Trader (trade) and Viewer (read-only). An Admin creates users via POST /api/v1/auth/register.

چرا مستندات برخی چیزها را «ناقص» می‌نامند؟ Why do the docs call some things incomplete?

چون واقعاً ناقص‌اند. نسخهٔ قبلی مستندات چیزهایی را ادعا می‌کرد که کد پشتیبانی نمی‌کرد. ما ترجیح می‌دهیم یک شکاف را صادقانه اعلام و در نقشهٔ راه ثبت کنیم تا اینکه ادعای نادرستی بکنیم. ممیزی کامل ۴۵ یافته در docs/AUDIT.md موجود است.

Because they genuinely are. The previous documentation claimed things the code did not support. We would rather state a gap honestly and track it in the roadmap than make a false claim. The full audit of 45 findings is in docs/AUDIT.md.

چطور مشارکت کنم؟ How do I contribute?

از CONTRIBUTING.md شروع کنید. هر Pull Request باید هم تست بک‌اند و هم راستی‌آزمایی فرانت را سبز نگه دارد؛ CI هر دو را دوباره بررسی می‌کند. حتی اصلاح یک اشتباه تایپی در مستندات کمک واقعی است.

Start with CONTRIBUTING.md. Every pull request must keep both the backend tests and the frontend verification green; CI re-checks both. Even fixing a documentation typo is a genuine contribution.
